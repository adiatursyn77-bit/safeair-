# Схема Firestore — приложение отслеживания утечек газа

## Коллекции

### `users/{uid}`

Профиль пользователя приложения (создаётся при первом входе через Firebase Auth).

| Поле         | Тип        | Описание                                              |
|--------------|------------|--------------------------------------------------------|
| `fcmTokens`  | `array<string>` | FCM-токены всех устройств, где пользователь вошёл в приложение. Push шлётся на все токены сразу. |
| `createdAt`  | `timestamp` | Когда пользователь зарегистрировался                  |

Токены добавляются/удаляются приложением при логине/логауте/обновлении токена Firebase Messaging.

---

### `devices/{deviceId}`

Одна физическая плата ESP8266 = один документ. `deviceId` — уникальный идентификатор платы (например, MAC-адрес чипа без двоеточий, `ESP.getChipId()` в hex, или просто случайный UUID, прошитый в код платы один раз).

| Поле         | Тип        | Описание                                              |
|--------------|------------|--------------------------------------------------------|
| `ownerUid`   | `string`   | UID владельца (для проверки прав доступа)             |
| `name`       | `string`   | Название платы, задаёт пользователь ("Кухня", "Гараж") |
| `secretHash` | `string`   | SHA-256 хэш секретного ключа платы (сам секрет — только в прошивке и в Cloud Function config, никогда в Firestore в открытом виде) |
| `lastSeenAt` | `timestamp`| Обновляется при каждом heartbeat от платы. Приложение считает плату offline, если `now - lastSeenAt > 30 сек` (или другой порог) |
| `status`     | `string`   | `"ok"` \| `"alarm"` — текущее состояние платы          |
| `createdAt`  | `timestamp`| Когда плата была привязана к аккаунту                  |

**Привязка новой платы**: пользователь вводит в приложении `deviceId` и секрет, которые видит на самой плате (например, наклейка с QR-кодом или выводится в Serial при первой прошивке). Приложение вычисляет `secretHash` на клиенте и создаёт документ. Секрет в чистом виде в Firestore никогда не попадает.

---

### `devices/{deviceId}/events/{eventId}`

Подколлекция — история утечек газа для конкретной платы. Пишется **только** Cloud Function (Admin SDK обходит security rules), приложение — только читает.

| Поле          | Тип         | Описание                                             |
|---------------|-------------|--------------------------------------------------------|
| `type`        | `string`    | `"leak_start"` \| `"leak_end"`                        |
| `startedAt`   | `timestamp` | Момент начала утечки (`time(nullptr)` с платы, в UTC) |
| `endedAt`     | `timestamp \| null` | Момент устранения (`null`, пока утечка активна) |
| `durationSec` | `number \| null` | Длительность в секундах (`null`, пока активна)   |

Одно **событие утечки** = один документ, который сначала создаётся с `type: "leak_start"` и `endedAt: null`, а при устранении **обновляется** (не создаётся новый документ) — добавляются `endedAt` и `durationSec`, `type` меняется на `"leak_end"`. ID документа для обновления Cloud Function хранит в памяти между вызовами (или передаётся платой как `eventId`, сгенерированный при старте тревоги).

## Индексы

Для сортировки истории по времени (используется по умолчанию, композитный индекс не нужен, если сортировка только по одному полю):

```
Collection: devices/{deviceId}/events
Order by: startedAt DESC
```

Firestore создаёт это автоматически при первом запросе с сортировкой — специально настраивать не нужно.

---

## Почему `secretHash`, а не сам секрет

Секрет генерируется один раз при первой прошивке платы (например, случайная строка 32 символа) и:
- прошивается в код ESP8266 (`const char* deviceSecret = "...";`),
- хэшируется на клиенте при привязке платы в приложении и сохраняется как `secretHash` в Firestore,
- хранится в открытом виде **только** в конфиге Cloud Function (Firebase Functions config/Secret Manager) для сверки при каждом запросе от платы.

Так даже при компрометации базы Firestore (например, кто-то получит доступ на чтение) секреты плат не раскрываются.
